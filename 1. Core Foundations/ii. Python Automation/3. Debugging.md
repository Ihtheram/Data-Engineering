## **Debugging**
Debugging in programming is the process of finding, analyzing, and fixing errors (bugs) in code so the program behaves as intended. 

Python offers tools like **exception handling** to handle errors, **assertions** to check assumptions, and **logging** to track what the program does, making it easier to spot issues. 

**Why debugging matters**
- Prevents unexpected behavior in production
- Improves code reliability and maintainability
- Helps you understand your own logic more deeply
- Builds confidence when working with larger data engineering pipelines

**Common debugging techniques**
* **Printing** variable values (print() debugging)
* Using **breakpoints** and stepping through code
* Reading **error messages** carefully
* Checking **assumptions** about data types and values
* Using **logging** for more complex systems

### **I. Exception Handling**
Exception handling is Python’s way of managing errors gracefully so the program doesn’t crash unexpectedly.

**Purpose**
- Prevents program termination
- Allows fallback behavior
- Helps isolate where and why something failed

**Core Syntax**
```python
try:
    risky_operation()
except ValueError:
    print("Handled a ValueError")
except Exception as e:
    print("Something went wrong:", e)
else:
    print("No errors occurred")
finally:
    print("This always runs")
```
**When to use it**
- File operations
- Network/API calls
- Database queries
- User input validation
- Automation scripts where reliability matters

### **II. Assertions**
Assertions are internal self-checks used to verify that certain conditions are true during development.

**Purpose**
- Catch programming mistakes early
- Document assumptions in code
- Fail fast when something is logically impossible

**Syntax**
```py
assert condition, "Error message if condition is False" 
```
**Example**
```py
assert len(data) > 0, "Data should not be empty"
```
*Note: Assertions can be disabled when running Python with optimization flags, so they should not be used for runtime validation or user input checking.*

### **III. Logging**
Logging is the practice of recording events, errors, and diagnostic information while a program runs.

**Purpose**
- Track what your program is doing
- Debug issues in production
- Store historical information
- Replace excessive print() debugging


#### **Python Logging Levels** (from least to most severe)
The logging module records events at different levels (DEBUG, INFO, WARNING, ERROR, CRITICAL). 

**Import logging and set level**
```python
import logging 
logging.basicConfig(level=logging.DEBUG) 
```

1. **DEBUG**

    **Purpose**:  
    Detailed diagnostic information for developers.

    **When to use:**
    - Tracing variable values
    - Understanding control flow
    - Investigating tricky bugs
    - Logging SQL queries, API payloads, or intermediate data

    **Example:**
    ```python
    logging.debug("Loaded 12 records from the API")
    ```

2. **INFO**

    **Purpose:**
    General events that confirm the program is working as expected.

    **When to use:**
    - Start/end of major steps
    - Successful completion of tasks
    - High-level pipeline progress

    **Example:**
    ```python
    logging.info("Data ingestion completed successfully")
    ```

3. **WARNING**

    **Purpose:**
    Something unexpected happened, but the program can still continue.

    **When to use:**
    - Retry attempts
    - Missing optional configuration
    - Slow response times
    - Deprecated API usage

    **Example:**
    ```python
    logging.warning("Retrying connection: attempt 2 of 3")
    ```

4. ERROR

    **Purpose:**
    A serious issue occurred; the program couldn’t perform a specific operation.

    **When to use:**
    - Failed database write
    - API request failed after retries
    - File not found
    - Invalid data format

    **Example:**
    ```python
    logging.error("Failed to write to database: %s", err)
    ```

5. CRITICAL

    **Purpose:**
    A severe error that may cause the entire program to stop.

    **When to use:**
    - System-wide failure
    - Corrupted data
    - Unrecoverable exceptions
    - Pipeline must halt immediately

    **Example:**
    ```python
    logging.critical("Pipeline aborted due to corrupted input file")
    ```

**Why logging matters in automation**
- Helps diagnose failures in scheduled jobs
- Provides audit trails
- Makes debugging easier without modifying code


### Mini-Project: Robust File Processor 

#### **Reason**
File operations can fail due to missing files or permissions. This script handles such errors and logs them, ensuring robust automation. 

```python
import os 
import logging 

logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s') 

def process_file(file_path): 
    if not os.path.exists(file_path): 
        logging.error(f"File does not exist: {file_path}") 
        return 

    try: 
        with open(file_path, 'r') as f: 
            content = f.read() 

            # Process the content, e.g., count words 
            word_count = len(content.split()) 
            logging.info(f"Processed {file_path}: {word_count} words") 
    except Exception as e: 
        logging.error(f"Error processing {file_path}: {e}") 

# Example usage 
process_file('existing.txt') 
process_file('nonexistent.txt') 
```

#### **Explanation**

This script checks if a file exists, reads it, counts words, and logs the result. Errors are caught and logged, preventing crashes.
